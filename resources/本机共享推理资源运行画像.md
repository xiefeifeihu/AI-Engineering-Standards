# 本机共享推理资源运行画像 (Machine Shared Inference Runtime Profile)

```text
RESOURCE_SPEC_VERSION=V0.1
RESOURCE_SPEC_STATUS=PRE_RELEASE
PROFILE_SCOPE=MACHINE_LOCAL_SHARED
FINAL_RELEASE_PENDING=true
```

> **安全与标准原则**：
> 1. 本画像记录当前开发机已就绪的共享推理资源物理运行基线；
> 2. **零密钥红线**：严禁记录任何真实 API Key、Token、密码或私有凭证；
> 3. **动态模型清单**：可用模型列表通过动态接口实时发现，严禁在此硬编码静态模型列表；
> 4. **网络解耦**：严禁硬编码任何动态网桥 IP（如 172.17.x.x / 172.18.x.x）。

## 2. 详细资源运行契约

### 2.1 资源 1：Ollama 本地实例 (`ollama-local`)
- **协议类型**：`ollama`
- **宿主端点**：`127.0.0.1:11434`
- **容器访问**：通过宿主网关 `host.docker.internal:11434`（需配置 `host-gateway`）访问
- **认证模式**：无需凭据（`credential_type: none`）
- **动态发现接口**：
  ```bash
  curl -s http://127.0.0.1:11434/api/tags
  ```
- **核心定位**：本地自建模型、纯离线任务兜底、高敏感文档与私密代码推理，零公网出站。

### 2.2 资源 2：Local CPA 实例 (`cpa-local`)
- **协议类型**：`cli_proxy_api` (CPA / CLIProxyAPI)
- **宿主端点**：`127.0.0.1:8317`
- **容器访问**：通过宿主网关 `host.docker.internal:8317` 访问
- **管理界面**：`http://127.0.0.1:8317/management.html`
- **认证模式**：
  - 凭证引用标识：`local_cpa_key`
  - 凭据类型：`api_key` (`credential_type: api_key`)
  - 注入契约：HTTP Header `Authorization: Bearer <TOKEN>`
  - 凭证所有者：各项目在自身隔离受控目录（如 `LocalConfig/`）或环境变量中持有
- **动态发现接口**：
  ```bash
  curl -s -H "Authorization: Bearer <TOKEN>" http://127.0.0.1:8317/v1/models
  ```
- **核心定位**：聚合国内高低时延通道（阿里百炼 CodingPlan、NVIDIA 等），境内网络直连，时延极低。

### 2.3 资源 3：Cloud CPA 隧道实例 (`cpa-cloud`)
- **协议类型**：`cli_proxy_api` (CPA / CLIProxyAPI)
- **宿主端点**：`127.0.0.1:18317`
- **容器访问**：通过宿主网关 `host.docker.internal:18317` 访问
- **传输拓扑**：本地 Windows OpenSSH 加密隧道转发至海外 VPS 回环 `127.0.0.1:8317`（VPS 公网防火墙严禁暴露 8317）
- **认证模式**：
  - 凭证引用标识：`cloud_cpa_key`
  - 凭据类型：`api_key`
  - 注入契约：HTTP Header `Authorization: Bearer <TOKEN>`
  - 凭证所有者：各项目在自身隔离受控目录中持有
- **动态发现接口**：
  ```bash
  curl -s -H "Authorization: Bearer <TOKEN>" http://127.0.0.1:18317/v1/models
  ```
- **隧道运维责任与共享边界**：
  - **所有权**：由 `ai-kb-infra` 项目持有和管理隧道生命周期（`scripts/tunnel/cloud-cpa-tunnel.cmd`）；
  - **消费方**：本机其他工程（如 VTIP、独立 Agent）直接作为 Client 消费 `127.0.0.1:18317`，无需复制代码或重复启动隧道；
  - **运行属性**：可选按需资源（On-demand / Optional），离线时不影响机器网络与基础本地推理。

## 3. 跨工程消费者接入指引

### 3.1 宿主机环境直接消费 (Host Direct Access)
宿主机上的 Python 脚本、Node.js 进程、CLI 工具等：
- 直接连接 `127.0.0.1:11434` / `127.0.0.1:8317` / `127.0.0.1:18317`。
- 请求头注入从项目本地安全位置读取的 Token。

### 3.2 Docker 容器跨主机网关访问 (Container Access via Host Gateway)
因宿主机 `cpa-local` (8317) 与 `cpa-cloud` (18317) 严格执行 `127.0.0.1` 本地回环绑定，跨项目容器访问由基础设施常驻 **Machine Docker Shared Inference Gateway**（网桥内部轻量转发器）支撑：
- **常驻与自启保障 (Producer Cold-Start Contract)**：
  - 注册为系统级服务：`docker-inference-gateway.service`
  - 随 Docker 守护进程开机自启（`systemctl is-enabled` -> `enabled`），冷重启自动拉起；
  - 提供 CLI 管理工具：`scripts/network/inference-gateway.cmd` / `ops/network/docker-inference-gateway.sh`，统一对接 `systemctl`。
- **动态网桥发现与自愈 (Dynamic Bridge Discovery)**：
  - 网关运行期动态轮询（5s 周期）扫描所有活跃 Docker bridge 接口（`docker0`, `br-*`）；
  - 新项目创建自定义 bridge 后，网关自动拉起新网桥的监听；网络销毁后优雅关闭陈旧监听；
  - 启动容错：冷重启初期网桥未就绪时采用退避重试（Backoff），不崩溃不空转；
  - 端口绑定隔离：宿主 Ollama 必须发布于 `127.0.0.1:11434:11434`，与网关监听各 Docker bridge `172.x.0.1:11434` 完美共存，杜绝 `0.0.0.0` 冷启动争抢冲突。
- **物理安全红线**：
  - 仅监听 Docker bridge 内部接口，**严禁监听 0.0.0.0 或 LAN (192.168.10.x)**；
  - 内置客户端 ACL，严格仅放行容器网桥与回环网段（`172.16.0.0/12`、`10.0.0.0/8`、`127.0.0.1`）；
  - 离线表现：Cloud CPA 隧道未启动时，网关快速返回 HTTP 502 / 连接拒绝（时延 < 1ms），绝不越权拉起外部隧道。

### 3.3 项目消费契约声明规范 (Consumer Declaration Contract)
各项目在自身工程画像中必须明确声明 `shared_inference_consumption`：
1. **`NONE`**：核心服务不消费共享推理资源（如 `vtip-platform-catalog` 核心容器），保持 compose 纯净，严禁注入 `extra_hosts`；
2. **`OPTIONAL`**：按需消费或通过独立 AI 组件接入（如 `vtip-ai-sidecar`），仅在 AI 容器中注入 `extra_hosts`；
3. **`REQUIRED`**：核心业务强依赖共享推理资源（如 `AI-KB`），容器编排注入 `extra_hosts` 并纳入必选门禁。

在依赖共享推理的容器服务中接入契约：
```yaml
services:
  your-ai-service:
    extra_hosts:
      - "host.docker.internal:host-gateway"
    environment:
      - OLLAMA_ENDPOINT=http://host.docker.internal:11434
      - CPA_LOCAL_ENDPOINT=http://host.docker.internal:8317
      - CPA_CLOUD_ENDPOINT=http://host.docker.internal:18317
```
**安全禁止**：
- 严禁硬编码特定宿主 IP（如 `192.168.x.x`）或特定 Docker 网桥 IP（如 `172.17.x.x` / `172.18.x.x`）；
- 严禁为了容器通信将宿主机服务的绑定扩大到 `0.0.0.0`。

## 4. 故障隔离与降级守卫原则

1. **Offering Health 与 Resource Health 解耦**：
   - 某模型 401 鉴权失败或 404 不存在，不得判定为物理端口或网络离线；
2. **严禁无条件本地 Fallback**：
   - 云端/远端不可用时，系统必须根据项目调度策略、数据敏感度合规性、`production_approved` 状态及能力契约（如 Vision 必须匹配）决定降级或阻断。
